# RHEL 7.9 → 8.10 Leapp 업그레이드 실무 경험 정리

## 들어가며

RHEL 7은 2024년 6월에 유지관리 지원이 종료되면서 8 이상으로의 업그레이드가 필수가 되었습니다. 이번에 실제 고객사 환경에서 **Leapp**을 이용해 RHEL 7.9에서 8.10으로 In-Place 업그레이드를 진행한 과정과 그 과정에서 마주했던 문제들을 정리합니다.

이번 작업의 특징은 다음과 같습니다.

- **ISO 기반 업그레이드**: 내부망 환경이라 RHSM 저장소가 아닌 RHEL 8.10 DVD ISO를 직접 사용
- **`--no-rhsm` 옵션 사용**: 서브스크립션 등록 없이 진행
- **스냅샷 기반 롤백 대비**: 업그레이드 전 7.9 스냅샷 생성

> ⚠️ Leapp 업그레이드는 SELinux를 자동으로 활성화하고, 서브스크립션을 비활성화합니다. 진행 전 반드시 백업(스냅샷)을 확보하세요.

**작업 순서 요약**
1. 사전 준비 (스냅샷, leapp 패키지 확보)
2. preupgrade 검사 및 inhibitor 해소
3. 업그레이드 실행
4. 업그레이드 후 정리 작업 (구 커널, el7 패키지 제거)

---

## Part 1: 사전 준비

### 1.1 스냅샷 생성

업그레이드 실패에 대비해 **RHEL 7.9 상태의 스냅샷**을 먼저 생성했습니다. Leapp 업그레이드는 한 번 진행하면 되돌리기 어렵기 때문에 롤백 수단은 필수입니다.

### 1.2 leapp 패키지 다운로드

내부망 환경이라 leapp 관련 패키지를 외부에서 RPM으로 미리 받아왔습니다. 필요한 패키지는 다음 5가지입니다.

- `leapp`
- `leapp-deps`
- `python2-leapp`
- `leapp-upgrade-el7toel8`
- `leapp-upgrade-el7toel8-deps`

leapp는 **rhel-7-server-extras-rpms** 저장소에서 제공되므로, 다운로드용 머신에서 서브스크립션을 잠시 활성화합니다.

```bash
subscription-manager repos --enable=rhel-7-server-extras-rpms
```

의존성까지 한 번에 받기 위해 `yumdownloader --resolve`를 사용했습니다.

```bash
yumdownloader --resolve \
  leapp \
  leapp-deps \
  python2-leapp \
  leapp-upgrade-el7toel8 \
  leapp-upgrade-el7toel8-deps
```

총 30개의 RPM을 받았고, 다 받은 뒤에는 서브스크립션을 정리합니다.

```bash
subscription-manager unregister
yum clean all
```

대상 서버에 RPM을 옮겨 설치합니다. 기존 저장소 설정이 간섭하지 않도록 `--disablerepo='*'`를 붙였습니다.

```bash
yum --disablerepo='*' localinstall /root/leapp-test/*.rpm
```

### 1.3 RHEL 8.10 ISO 준비

업그레이드에 사용할 **RHEL 8.10 DVD ISO 원본**이 필요합니다. USB에 폴더를 하나 만들어 ISO를 담아 서버로 전달했고, `/home/con/` 아래에 위치시켰습니다.

설치 후 `yum repolist`로 현재 저장소 상태를 확인해 둡니다.

## Part 2: preupgrade — 업그레이드 가능 여부 검사

### 2.1 preupgrade 실행

실제 업그레이드 전에 반드시 `leapp preupgrade`로 사전 점검을 진행합니다.

```bash
leapp preupgrade \
  --target 8.10 \
  --no-rhsm \
  --iso /home/con/rhel-8.10-x86_64-dvd.iso
```

### 2.2 inhibitor: pata_acpi 커널 드라이버

preupgrade 결과에서 가장 먼저 걸린 문제는 **pata_acpi 커널 드라이버**였습니다. 이 드라이버는 RHEL 7.9에는 있지만 8.10에서는 삭제된 커널 드라이버로, 로드되어 있으면 업그레이드가 차단(inhibit)됩니다.

실제 사용 중인지 확인:

```bash
lspci -nnk | grep -A3 -Ei 'storage|sata|ide'
```

확인 결과 실제로 사용 중이 아니라 로드만 되어 있는 상태라서 안전하게 제거할 수 있었습니다.

```bash
sudo rmmod pata_acpi
lsmod | grep pata_acpi
```

### 2.3 initramfs 재생성

드라이버 제거 후 initramfs를 다시 생성합니다.

```bash
dracut -f --regenerate-all
```

### 2.4 answerfile 관련 에러

진행 중 answer 파일 누락 관련 에러가 발생하면 다음과 같이 응답을 등록해 줍니다.

```bash
leapp answer --section remove_pam_pkcs11_module_check.confirm=True
```

### 2.5 그 외 확인 사항

- **e1000 네트워크 드라이버**: RHEL 8부터 제거 대상이 되는 커널 드라이버로, VM 환경에서 주로 발생합니다. 이번 환경이 VM이라 해당 사항을 확인했습니다.
- **기존 7.9 저장소 비활성화**: 기존 RHEL 7.9 repo는 잠시 비활성화해 둡니다.
- preupgrade 결과 **inhibit 사항이 없다면** 업그레이드 가능한 상태입니다.

## Part 3: 업그레이드 실행

preupgrade에서 문제가 없음을 확인했으면 실제 업그레이드를 실행합니다.

```bash
leapp upgrade --target 8.10 --no-rhsm --iso /home/con/rhel-8.10-x86_64-dvd.iso
```

업그레이드가 완료되면 시스템이 재부팅되는데, 정상적으로 부팅되었다면 커널 버전으로 확인합니다.

```bash
uname -r
```

8.10 커널(`*.el8*`)로 부팅에 성공했다면 업그레이드는 성공입니다. 하지만 여기서 끝이 아닙니다. **구 커널과 이전 버전 패키지 정리**라는 사후 작업이 남아 있습니다.

---

## Part 4: 업그레이드 후 정리 작업

이 부분은 Red Hat 공식 문서를 기준으로 진행했습니다.

> 📖 참고: [Performing post-upgrade tasks (RHEL 7 to RHEL 8)](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/8/html/upgrading_from_rhel_7_to_rhel_8/performing-post-upgrade-tasks-rhel-7-to-rhel-8_upgrading-from-rhel-7-to-rhel-8)

### 4.1 yum exclude 설정 해제

```bash
yum config-manager --save --setopt exclude=''
```

### 4.2 구 커널(RHEL 7) 제거

먼저 el7 커널 모듈 디렉터리를 확인합니다.

```bash
cd /lib/modules && ls -d *.el7*
```

커널을 제거합니다.

```bash
[ -x /usr/sbin/weak-modules ] && /usr/sbin/weak-modules --remove-kernel 3.10.0-1160.el7.x86_64
```

부트로더에서도 제거합니다.

```bash
/bin/kernel-install remove 3.10.0-1160.el7.x86_64 /lib/modules/3.10.0-1160.el7.x86_64/vmlinuz
```

### 4.3 RHEL 7 패키지 제거

남아 있는 el6/el7 패키지를 찾아봅니다.

```bash
rpm -qa | grep -e '\.el[67]' | grep -vE '^(gpg-pubkey|libmodulemd|katello-ca-consumer)' | sort
```

제거합니다. 이때 **타사(third-party) 패키지도 함께 삭제될 수 있으니** 목록을 미리 확인해야 합니다.

```bash
yum remove kernel-workaround $(rpm -qa | grep \.el7 | grep -vE 'gpg-pubkey|libmodulemd|katello-ca-consumer')
```

leapp 관련 의존 패키지와 el7 흔적을 정리합니다.

```bash
yum remove leapp-deps-el8 leapp-repository-deps-el8
rm -r /lib/modules/*el7*
rm -f /etc/pki/product/204.pem
```

### 4.4 RHEL 8.10 저장소 구성

새로운 버전에 맞춰 **BaseOS / AppStream** 저장소를 구성합니다. (ISO 기반이라면 ISO 내 `BaseOS/`, `AppStream/` 디렉터리를 repo로 지정)

### 4.5 rescue 커널/이미지 재생성

현재 커널과 디스크에 맞는 rescue 이미지를 다시 만들어 줍니다.

```bash
yum -y install dracut-config-rescue
rm /boot/vmlinuz-*rescue* /boot/initramfs-*rescue*
/usr/lib/kernel/install.d/51-dracut-rescue.install add "$(uname -r)" /boot "/boot/vmlinuz-$(uname -r)"
```

### 4.6 최종 확인

부트로더에 구 커널이 남아있지 않은지 확인:

```bash
grubby --info=ALL | grep "\.el7" || echo "Old kernels are not present in the boot loader."
```

새로 생성한 rescue 커널/이미지 확인:

```bash
ls /boot/vmlinuz-*rescue* /boot/initramfs-*rescue*
lsinitrd /boot/initramfs-*rescue*.img | grep -qm1 "$(uname -r)/kernel/" && echo "OK" || echo "FAIL"
grubby --info $(ls /boot/vmlinuz-*rescue*)
```

RHEL 7 패키지가 모두 제거되었는지 최종 점검:

```bash
rpm -qa | grep -e '\.el[67]' | grep -vE '^(gpg-pubkey|libmodulemd|katello-ca-consumer)' | sort
```

### 4.7 Python 기본 버전 설정

RHEL 8.10으로 업그레이드한 뒤에는 시스템 기본 Python을 지정해 줍니다.

```bash
alternatives --set python /usr/bin/python3
```

## 마치며

정리하면 이번 업그레이드의 핵심 포인트는 다음과 같습니다.

1. **스냅샷은 필수** — 롤백 수단이 있어야 과감하게 진행할 수 있습니다.
2. **preupgrade를 반드시 먼저** — pata_acpi처럼 환경마다 다른 inhibitor를 미리 발견해 해소합니다.
3. **ISO 기반 + `--no-rhsm`** — 내부망/서브스크립션 제약 환경에서도 업그레이드가 가능합니다.
4. **사후 정리가 반** — 업그레이드 성공 후 구 커널, el7 패키지, rescue 이미지 정리까지 끝내야 완료입니다.

RHEL 7 EOL이 지나면서 같은 작업을 앞두고 계신 분들에게 이 글이 참고가 되길 바랍니다.
